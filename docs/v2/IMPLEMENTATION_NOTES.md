# Pumpkin 2.0 — технические требования и приёмка

Статус: план интеграции после согласования дизайна. Этот документ не подтверждает реализацию или тестирование Pumpkin 2.0. Дата среза исходных программ: 2026-10-01.

## 1. Исходные программы

Фиксированные ссылки позволяют отличать изученную версию от дальнейших изменений соседних проектов.

| Источник | Изученная ревизия | Что использовать |
| --- | --- | --- |
| [Pumpkin 1.0](https://github.com/baogli/pumpkin/tree/400d030829113d3b6fe8de58b4ce46a920c09ca4) | `400d030` | Наблюдатели, определение скриншотов/готовых скачиваний, таймеры, файловая идентичность, Корзина, возврат, состояние и миграции |
| [Vee](https://github.com/baogli/vee/tree/6afc509e8516fcfe3562fb07edc29a1ec2160744) | `6afc509` | История текста в RAM, защищённые типы pasteboard, положение у курсора, клавиатурный popup, доставка вставки |
| [Able Recorder 0.2.0](https://github.com/baogli/able-recorder/tree/099938c97b47b28abfd0e48a0b1010101b7a3bc0) | `099938c` | Core Audio устройства/каналы, AUHAL, ScreenCaptureKit, MP4 через AVAssetWriter, мониторинг и медиа-проверки |

Pumpkin и Able Recorder имеют MIT-лицензии. У изученной версии Vee явная лицензия в репозитории не обнаружена; GitHub также не определяет лицензию. До включения её кода в публичный Pumpkin требуется подтвердить авторство и право распространения, оформить лицензию и атрибуцию. Публичность репозитория сама по себе не даёт права копировать код. Эта проверка не препятствует дизайну: настоящий пакет содержит требования, а не скопированный код Vee.

Рабочее название версии — 2.0. Номер существующей сборки, текущий тег и релиз 1.0 не меняются на этапе спецификации.

## 2. Модули и границы

Нативный Swift/AppKit/SwiftUI, C для аппаратного audio callback. Базовая цель macOS 14+. Одна идентичность приложения `app.pumpkin.Pumpkin`, один status item, один обработчик глобальных hotkeys. Возможное разбиение пакетов:

| Модуль | Ответственность |
| --- | --- |
| PumpkinCore | Существующая файловая логика, таймеры, восстановление, миграция состояния |
| PumpkinClipboard | Наблюдение pasteboard, RAM-история, фильтры, контекст цели, безопасная вставка |
| PumpkinRecorder | Устройства, захват дисплея, аппаратный звук, мониторинг, кодирование, завершение MP4 |
| PumpkinApp | Общее состояние, окна и меню, разрешения, координация popup, настройки и локализация |

Имена модулей — предложение, их можно адаптировать при разработке. Запись и вставка не должны находиться внутри UI-компонентов; UI вызывает операции и отображает их результат. Обработка файлов и сохранение метаданных не должны блокировать аппаратный звуковой callback.

Сохранить архитектуру recorder: preallocated AUHAL ring buffer, атомарные индексы, без выделения памяти, блокировок и Swift-callback на real-time потоке. Экран и звук используют общую host-clock временную шкалу. Независимость L/R, конверсия sample rate, последний статичный кадр и корректное завершение MP4 сохраняются при переносе.

Не включать в сборку разработческие self-test режимы, которые автоматически захватывают реальный рабочий стол или используют конкретную карту без явного запуска. Синтетические media self-tests должны оставаться самостоятельным способом проверки.

## 3. Состояния и координация

### 3.1. Recorder

`idle → preparing → countdown → recording → finalizing → saved / failed`.

Отдельный путь проверки звука: `idle → preparingMonitor → monitoring → stoppingMonitor → idle / failed`. Мониторинг не создаёт видео. Кнопка записи из monitoring сначала останавливает мониторинг, затем проверяет/запускает запись. Устройство не открывается двумя независимыми сессиями одновременно.

Отмена подготовки/отсчёта возвращает idle и освобождает ресурсы. Hotkey ⌃⇧R: idle запускает с валидными настройками либо открывает настройку; monitoring останавливает проверку и начинает подготовку; preparing/countdown отменяет; recording останавливает; stoppingMonitor/finalizing игнорирует повторный вызов с видимым статусом.

На этапе подготовки/мониторинга/записи источник и формат не изменяются на лету. Для смены устройства пользователь сначала завершает текущую операцию. «Без звука» требует отдельной реализации pipeline без аудиотрека и без Microphone-запроса.

После отказа источника не возвращаться молча к idle: сохранить исходную причину и результат финализации. События остановки идемпотентны; двойной Stop/отключение устройства не вызывают двойное завершение writer.

Sleep/блокировка сессии/системная остановка захвата должны приводить к понятному статусу и попытке финализации; не обещать фоновую запись заблокированного Mac. Если приложение успевает обработать shutdown, оно завершает запись; потеря питания/force quit остаётся ограничением.

### 3.2. Clipboard

Состояние сбора: enabled / paused / disabled. Разрешение AX — отдельное состояние. Popup: hidden / visibleInsert / visibleCopy / delivering / failed. Любая попытка вставки хранит исходную цель и token операции; новый popup не должен наследовать устаревшую цель.

Для временной подмены pasteboard нужен snapshot всех представлений и ownership token/changeCount собственной записи. Восстановление допускается только если системный буфер не изменился после нашей записи. Если пользователь скопировал новый текст, оставить новый буфер. Если целевое приложение/окно больше не соответствует контексту, отменить автоматическую доставку и предложить копирование.

Нельзя объявлять текст «вставленным» на основании одного отправленного ⌘V: внешнее приложение может не принять событие. В таких случаях UI подтверждает отправку команды либо копирование, а ошибка доставки предлагает понятный выход.

В основной истории числа не являются глобальными shortcut. Регистрация 1–9, стрелок и Return действует только при открытом popup. Ввод в другом приложении не перехватывается в закрытом состоянии.

### 3.3. Cleanup и PopupCoordinator

Пауза таймеров сохраняет текущую логику сдвига срока; ни состояние recorder, ни clipboard её не переключает автоматически. Отключение наблюдения источника прекращает новые запросы и не отменяет подтверждённые таймеры.

PopupCoordinator разрешает только одно интерактивное transient-окно. Явный clipboard popup имеет приоритет перед автоматическим запросом срока. Во время подготовки/отсчёта/записи/финализации автоматические запросы и toast откладываются. После завершения — результат записи, сводка событий, затем обычная очередь; не показывать серию окон поверх результата.

Новый файл, найденный в этот период, попадает в список «Ждут решения». Для него ещё нет expiresAt. Таймаут политики без ответа запускается при фактическом показе вопроса. Данные ожидающих решений не пропадают при обычном перезапуске; после запуска повторно проверять существование/идентичность файла, и никогда не превращать сохранённый скрытый вопрос в подтверждённый таймер.

Окна Pumpkin исключаются из ScreenCaptureKit-фильтра. Это необходимо проверить для главного окна, меню, быстрых popup и диалогов; нельзя считать доказательством один скрытый главный window. Чужие окна, уведомления и текст, который пользователь вставляет в записываемое приложение, не маскируются.

## 4. Данные и файловая безопасность

| Сущность | Где живёт | Основные поля / правило |
| --- | --- | --- |
| ClipboardItem | Только RAM | id, text, copiedAt, тип превью; максимум 60, точный dedupe |
| RecordingSettings | Локальные preferences | Идентификатор дисплея, стабильный UID устройства, каналы, формат, папка; перед запуском перевалидировать |
| RecordingEntry | Локальный manifest | id, файловая ссылка/bookmark и identity, createdAt, duration, size, формат, происхождение, finished/failed; не дублировать MP4 |
| TrackedItem / TrashRecord | Существующее файловое состояние | id, identity, исходная папка, срок/Корзина; расширить происхождением recording без потери старых данных |
| PendingFile | Локальное состояние очереди | Файловая идентичность, источник, время обнаружения; не содержит подтверждённого срока |
| Permissions | Состояние системы + UI | Перечитывать; кеш не является доказательством доступа |

Конкретная схема и bookmarks зависят от модели sandbox/signing; разрешение папки получать системным способом, не требовать доступ ко всему диску ради одной папки. Диагностика должна исключать clipboard text, содержимое файлов и лишние личные пути; пользовательские пути нужны в собственном UI, но не в публичных логах/артефактах QA.

Перед созданием `.partial.mp4` зарегистрировать активную/будущую запись в общем реестре защиты. При финализации обновлять manifest и известную файловую идентичность атомарно настолько, чтобы наблюдатель Downloads не назначил срок между сменой имени и обновлением состояния. Имена файлов уникальные, чужие файлы не перезаписываются.

Реестр собственных записей защищает готовые MP4 при рестарте, смене папки и повторном обнаружении watcher. Защита определяется происхождением/идентичностью, а не только шаблоном `Recording_*`: пользовательский download с похожим именем остаётся обычным файлом. Все `.partial.mp4` исключаются из автоматической очистки; только зарегистрированные части Pumpkin отображаются как его незавершённые записи.

Явно назначенный таймер собственному видео работает через общий expiry engine с исходной папкой как границей, без включения очистки всех соседних файлов Movies. Запись и таймер ссылаются на один файл. Переименование обновляет представление, перенос наружу снимает право очистки, пустой/подменённый path не считается тем же объектом.

MP4 заканчивается в `.partial.mp4`, затем становится конечным `.mp4` после успешного завершения. При ошибке сохранить доступную часть и метаданные причины; не обещать, что файл можно проиграть или починить. После crash приложение может показать обнаруженный зарегистрированный partial с Finder-действием и объяснением. Безусловного удаления таких файлов нет.

Недостаток места: до старта проверить доступность папки/диска; при достоверно низком свободном месте предупредить, во время записи отслеживать ошибки и попытаться корректно закончить файл. Оценка размера — bitrate-based ориентир, а не гарантия, что хватит места на любую длительность.

Сроки и очередь — versioned state с безопасной миграцией и резервной копией. История буфера в этот state не включается ни прямо, ни в виде превью. Записи и таймеры сохраняются при выходе; текстовая история очищается.

## 5. Обновление существующих установок

1. Pumpkin 1.0 → 2.0: сохранить идентичность Pumpkin, действующие таймеры, паузу, watched folders, историю Корзины и настройки. Миграция повторяемая, с backup и обработкой повреждённого состояния. Уже выполненный импорт ShelfLife не запускать повторно поверх новых настроек.
2. Vee: историю RAM не обещать перенести. По явному выбору пользователя можно перенести нечувствительные preferences и hotkey; текст не записывать на диск ради миграции.
3. Able Recorder: предложить импорт настроек; заново проверить дисплей, UID устройства и L/R. Импорт прошлых видео — явный выбор файлов/папки с показом списка, без автоматической очистки. Не перемещать исходные видео самостоятельно.
4. Старые приложения продолжают существовать отдельно. Показать подсказку закрыть Vee/Able Recorder и отключить их автозапуск при переходе, чтобы не было двойного наблюдения и конфликтов. Не удалять и не завершать другие приложения молча.
5. Разрешения Vee и Able Recorder не считаются разрешениями Pumpkin. Запросить недостающие системные доступы для новой объединённой функции в нужный момент. Пользовательские настройки macOS не изменять обходным способом.

Медиа-проверки должны анализировать законченный экспорт, а не только внутренние счётчики. Для A04/A05 использовать настоящий музыкальный сигнал и прослушивание, а не почти тихий вход. Для A09 записать длительность, декодированные timestamps, drift и ресурсные измерения; параметры допустимого drift определить до запуска теста и сообщить в отчёте.

QA использует временные файлы и синтетический clipboard text. Любой тест реального экрана — явный локальный запуск; записанный рабочий стол не коммитить. Файловые тесты возвращают тестовые объекты из Корзины и не затрагивают обычные пользовательские файлы.

## 7. Что уже проверено в исходных программах

- Pumpkin 1.0: локально прошли 60 tests и 80 end-to-end/UI checks. Эти результаты относятся к существующей версии очистки и не покрывают объединённую программу.
- Able Recorder 0.2.0: [синтетические проверки](https://github.com/baogli/able-recorder/blob/099938c97b47b28abfd0e48a0b1010101b7a3bc0/docs/TESTING.md) покрывают кодирование/полный decode, L/R, sample-rate conversion, длительность и контейнер.
- Его короткая аппаратная проверка дала MP4 примерно 3 секунды с видео и аудиотреком; вход был почти тихим. Это не подтверждение записи музыки Ableton или внешнего дисплея.
- Intel runtime, все интерфейсы, длительные сессии и полный пользовательский сценарий второго монитора ещё требуют проверки. Новое ядро буфера также должно пройти сценарии владения pasteboard и целей вставки после интеграции.

## 8. Порядок работ и будущий релиз

1. Согласовать дизайн по [DESIGN_BRIEF.md](DESIGN_BRIEF.md), отметить изменения поведения.
2. Проверить лицензии и перенести модули с сохранением существующих гарантий данных.
3. Реализовать общую оболочку, независимые разрешения и координацию.
4. Пройти матрицу приёмки, включая реальные аппаратные проверки и миграцию.
5. Подготовить публичную 2.0-сборку, README и release notes по фактически реализованным возможностям; отдельно указать статус signing/notarization.
6. Подготовить новые скриншоты и короткое демо с вымышленными данными. Анонс 2.0 не должен использовать интерфейсы 1.0 как доказательство готовых новых функций.

До выполнения этих этапов пакет публикуется только как спецификация для дизайна.

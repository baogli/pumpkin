# Pumpkin 🎃

**Record. Paste. Keep what matters.**

Pumpkin brings screen recording, recent clipboard text, and file expiry into one free, open-source macOS app. One menu bar icon opens a native Liquid Glass workspace; each module works independently.

Version **2.0 is available as a development preview in this branch**. The latest stable release remains 1.0. The [2.0 implementation and verification report](docs/v2/TESTING.md) distinguishes automated checks from physical audio/display and accessibility acceptance still to run.

- **Record:** choose one display, H.264 or HEVC MP4, 30/60 fps, and either no audio or an explicit hardware input and L/R pair. Check input levels before recording. Own recordings are kept forever until you explicitly set an expiry.
- **Paste:** opt in to a text-only, 60-item clipboard history held in RAM. Open the quick popup with **⌥⌘V**. Accessibility enables caret placement and automatic paste; copying works without it.
- **Clean up:** give downloads and real macOS screenshots an expiry. Expired files go to the Trash; Put Back restores them. Unanswered prompts keep files by default.

Russian and English, light/dark/system appearance, macOS 26 glass, and a macOS 14–15 material fallback are included. Capture and clipboard code never upload content or contact a server.

## Get Pumpkin

Requires **macOS 14 or later**. The release app contains both **Apple Silicon and Intel** binaries.

For the **stable 1.0 cleanup app**:

1. Download `Pumpkin-1.0.0-macOS.zip` from [the 1.0 release](https://github.com/baogli/pumpkin/releases/tag/v1.0.0).
2. Unzip it and drag `Pumpkin.app` into Applications.
3. Open Pumpkin. The welcome screen helps you grant Downloads and screenshot-folder access.
4. Look for the little pumpkin in your menu bar.

For the **2.0 development preview**, build this branch using the instructions below. Community builds are **ad-hoc signed and not Apple notarized**. macOS may block the first launch. Review the app and follow [Apple’s instructions for opening an app from an unidentified developer](https://support.apple.com/en-ie/102445), or build from source. The project does not require disabling Gatekeeper.

## Recording and clipboard

Start a recording from the Record section or **⌃⇧R**. The same shortcut stops and saves, cancels preparation/countdown, and ignores repeated presses during finalization. Closing the workspace keeps an ongoing recording running; quitting offers Stop and Quit and waits for MP4 finalization.

Audio is taken from the selected **Core Audio input**, including an audio interface's hardware loopback channels. Pumpkin does not install a virtual driver, change your interface routing, or capture generic system audio. Select and confirm L/R, then use Check Audio. Channel numbers belong to your device. No Audio creates a video-only MP4 and does not request Microphone access.

Recordings are written to a unique `.partial.mp4` and renamed only after successful completion. Failed/interrupted recordings remain visible with their error and a Finder action when a partial file exists; a partial MP4 may not be playable. All Pumpkin windows are excluded by the ScreenCaptureKit application filter. Other applications and notifications can appear in the recording.

Clipboard collection starts only after you enable it. Empty text and concealed, transient, or autogenerated pasteboard types are ignored. Pause retains the existing history; disabling or quitting clears it. Clipboard text is never written to the state file or diagnostic logs. In the popup, **1–9**, arrows, Return and Esc operate locally. They do not register as global typing shortcuts.

Automatic paste captures the original app/field, checks it again before sending ⌘V, and restores all original pasteboard representations only if Pumpkin still owns that temporary clipboard value. A newer user copy always wins. Sending a paste command cannot guarantee that every external app accepts it; if the original target is unavailable, Pumpkin offers Copy instead. Shortcut registration conflicts are shown in Settings, where both shortcuts can be changed.

## How it works

- **Download or take a screenshot.** A small question appears below the menu bar, with the file name and a preview when available.
- **Pick its midnight.** Choose 10 minutes, 30 minutes, an hour, a day, a week, or 30 days. Press **Done**, or **Keep Forever**.
- **Let Pumpkin tidy up.** Expired files go to the Trash. Click **Put Back** to restore them.
- **Change your plans.** Open Cleanup to adjust timers or keep a file. The menu bar menu includes **Pause**, **Settings**, and **Quit**.

The menu bar ring drains as the next file’s expiry approaches. An active recording takes status priority. Pause freezes timers; resuming shifts them by the paused duration. New files still wait for a decision while paused. Settings can start Pumpkin at login, change the watched download folder, disable either source independently, and control unanswered prompts. Disabling a source leaves confirmed timers running.

Automatic prompts/toasts are deferred while recording, using the quick clipboard, or viewing the workspace. Pending decisions persist across restarts without creating an expiry; their timeout begins when the question is actually shown. Recording completion presents an aggregate cleanup notice instead of a burst of prompts.

Once you click a question: **← →** pick a time, **Return** confirms, **K** keeps forever, and **Esc** dismisses it.

## Your files stay yours

Pumpkin runs locally. No accounts, telemetry, cloud uploads, or network requests.

- Files already in a folder on first launch are left alone. On later launches, Pumpkin can ask about files that arrived while it was closed, up to three days back.
- Only real macOS-tagged screenshots are watched in the screenshot folder; ordinary Desktop files are left alone.
- A file is moved to the Trash only while it is still the same file, identified by its inode, directly inside the folder where you set its timer. Renames are followed. Move it elsewhere, including a subfolder, and Pumpkin leaves it alone.
- Unfinished downloads such as `.crdownload`, `.part`, and `.download`, and all `.partial.mp4` files, are ignored.
- Own recordings are registered before writing starts and protected by their manifest/file identity across restarts. A downloaded file with a similar name does not gain that protection.
- Pumpkin never empties the Trash. Restoration remains available while the item is still there.

## Build from source

Use **Xcode 26 or later** and its Command Line Tools. The SDK is needed to compile the macOS 26 glass UI; the resulting app also includes the macOS 14–15 UI fallback.

```bash
swift test
scripts/build.sh
open dist/Pumpkin.app
```

The build produces a universal, ad-hoc-signed `dist/Pumpkin.app`. To package it:

```bash
scripts/package-release.sh
```

This creates the ZIP and `release/SHA256SUMS`. To sign with your own Developer ID, set `SIGN_IDENTITY="Developer ID Application: …"` when running `scripts/build.sh`. Notarization is a separate distribution step.

Recreate the original pumpkin icon with `swift scripts/make_icon.swift Resources`.

## Development and tests

There are no third-party Swift package dependencies.

| Path | Purpose |
| --- | --- |
| `Sources/PumpkinCore` | Folder watching, finished-download and screenshot detection, expiry, Trash, restoration, and persistence |
| `Sources/PumpkinApp` | Unified workspace, recording, RAM clipboard, menu bar/panels and independent permissions |
| `Sources/PumpkinAudioBridge` | Preallocated AUHAL audio ring and real-time callback in C |
| `Sources/Pumpkin` | Application entry point |
| `Sources/PumpkinQA` | Real app-model/UI checks and light/dark snapshots using temporary demo files |
| `Sources/PumpkinV2QA` | Unified UI layouts and keyboard/popup coordination checks with synthetic data |
| `Sources/PumpkinMediaQA` | Synthetic video/audio encoding and complete exported MP4 decode |
| `Tests` | Core logic and upgrade/settings migration tests |
| `media/launch` | Announcement MP4, portable editable composition, fonts, and launch copy |

```bash
swift test
scripts/qa-app.sh qa-output
swift run PumpkinV2QA /tmp/pumpkin-v2-ui
swift run PumpkinMediaQA /tmp/pumpkin-v2-media
```

See the [2.0 test report and remaining hardware checks](docs/v2/TESTING.md). QA uses temporary folders and the real Trash, restores its test files, and leaves ordinary user folders alone. UI checks require a local macOS graphical session. Run graphical QA apps one at a time. Local results do not imply a completed hosted CI run.

State lives in `~/Library/Application Support/Pumpkin/state.json`. Preferences use the `app.pumpkin.Pumpkin` defaults domain.

Upgrading 1.0 → 2.0 retains the bundle identifier, timers, watched folders, pause, and Trash history. The original state is backed up as `state.v1.backup.json` before the versioned state is written. New clipboard capture is disabled until you opt in. Screen Recording, Microphone and Accessibility permissions are independent and belong to Pumpkin, even if Vee or Able Recorder already have access. Importing their preferences is explicit; videos are imported through a file picker without moving them or setting a timer. Close the old apps and disable their login items yourself to avoid duplicate hotkeys.

Upgrading from the earlier local ShelfLife version: quit it before starting Pumpkin. Pumpkin copies its timers and imports its preferences once, retaining the original state as a backup. Existing Pumpkin preferences take precedence. Because the bundle identifier changed, macOS may ask for folder permissions again; configure **Open Pumpkin at login** in Settings and turn off the old login item if previously enabled.
